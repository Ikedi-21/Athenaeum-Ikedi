{% comment %} The search, category and sort controls that sit above a list of books. Shared by the public shelf and by the librarian's management list, which is the whole point: the two lists are driven by the same mixin in catalog/views.py, so they have to offer the same controls or one of them would quietly lack a way to reach half its own rows. Reads search_term, selected_category, selected_sort, sort_options and categories from the context, all five supplied by BookQueryMixin.get_context_data. It also reads category, which is present only on a single category page, and uses it to decide whether a category dropdown makes sense at all. There is no action attribute. A form without one submits to the address of the page it is on, which is exactly right for all three pages this appears on: the public list stays on the public list, the management list stays under manage/, and a category page keeps its own path so a search inside a category searches inside that category. Naming a URL here instead would send every search on a category page back out to the whole catalogue. method="get" rather than post, because a search is a request to read something. It also means the result has an address that can be bookmarked, shared, or reloaded without a browser warning about resending data, and it is what lets the pagination links carry the filters. No page field is included, so applying a filter drops the reader back to the first page. That is the correct behaviour: page nine of the old result set has nothing to do with the new one. {% endcomment %}
{% comment %} The value is fed back in so the box still holds what was typed after the page reloads. type="search" gives a clear button in most browsers. The name has to stay q, which is what BookQueryMixin.get_search_term reads. {% endcomment %}
{% comment %} The category dropdown is left out on a category page. The view there takes the category from the path and ignores any category in the query string, so a dropdown would be a control that appears to work and does nothing. A link back to the whole catalogue is offered instead, which is the thing somebody on that page would actually want. {% endcomment %} {% if not category %}

Anything else arriving in this parameter is ignored and the default is used, which is what stops a hand edited address from ordering the catalogue by somebody's password hash. {% endcomment %}
