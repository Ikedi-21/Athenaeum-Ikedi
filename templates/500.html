{% load static %} {% comment %} Shown when a view raises an unhandled exception and DEBUG is False. This one deliberately does not extend base.html. Django renders the 500 page without a request object, so no context processor runs and there is no user, no messages and no CSP nonce. More importantly, if whatever caused the error lives in base.html or in a context processor, extending it would fail a second time and the visitor would be left with Django's bare fallback text instead. A self contained page cannot fail that way. Nothing about the error is shown. The traceback goes to the server log and to the ADMINS email, where it is useful, and stays off a page a stranger can read, where it would describe the internals of the site. {% endcomment %} Something went wrong | Athenaeum Ikedi
